01 · Problem & Target Users Slide 02 / 08

Why Black-Box Revenue Agents Fail in Production

Today’s AI sales & reception agents evaluate incoming leads using only the text inside the chat window or a single CRM record. Because the ground truth is fragmented across Billing, Support, Product Telemetry, and Legal vaults, naive agents fail in three costly ways:

1. Deception & Bad-Debt Traps

A prospect claims "We have 50 active Pro seats in good standing—unlock Enterprise API today." A prompt-only LLM scores it 95/100 and auto-provisions keys to a 3-seat trial that owes $4,200 (47 days overdue).

2. Procurement Discount Bluffs

A buyer threatens to cancel at renewal unless given 45% off, claiming "our engineers barely use the tool." Without telemetry federation, the AI panics and faces a $27,900 discount bluff (45% demanded off $62k ARR → $22,940 net margin saved after enforcing the 8% MSA cap) when usage is actually 98.4%.

3. Zero Auditability ("Why 82?")

When an AI outputs an opaque score without row-level citations or counterfactuals, RevOps, Deal Desk, and local clinic owners refuse to trust or automate high-stakes actions.

04 · Sponsor Deep-Dive: Zetaris Networked Data Platform Slide 05 / 08

How Zetaris Was Used & What Made Our Approach Unique

1. 5-Silo Cross-Platform Federated Joins (Zero-ETL)

Instead of dumping raw CSVs into a vector DB, ZetarisClient executes a single federated SQL query across Snowflake, PostgreSQL, Intercom REST, S3/Iceberg, and Oracle/Ironclad with ZERO_ETL = TRUE.

2. Column-Level Security (MASK_CLS) & Read-Only MCP

Sensitive fields (personal_phone, card_fingerprint, bank_routing) are masked in-situ before reaching the agent. Any UPDATE/DELETE/DROP query is blocked with HTTP 403 and logged to the Zetaris audit trail.

3. Cryptographic Row Provenance & Counterfactual Pushdown

Every federated row returns a sha256 digest and pushdown predicate so clicking [SRC-1]–[SRC-5] proves the exact record that triggered the decision.

-- Zetaris Super MCP · 5-Silo Governed Query
SELECT
  c.record_id AS crm_id, c.verified_role,
  MASK_CLS(c.personal_phone) AS personal_phone,
  b.subscription_id, b.active_seats,
  b.past_due_usd, b.billing_status,
  MASK_CLS(b.card_fingerprint) AS card_fp,
  s.ticket_id, s.open_escalations, s.status,
  i.intent_score, i.usage_quota_pct,
  i.active_engineers_count, i.anomaly_flag,
  l.contract_id, l.max_discount_allowed_pct,
  l.allowed_payment_terms, l.required_signer
FROM zetaris_crm.hubspot_contacts c
JOIN zetaris_billing.stripe_subscriptions b
  ON c.account_key = b.account_key
LEFT JOIN zetaris_support.intercom_tickets s
  ON c.account_key = s.account_key
LEFT JOIN zetaris_intent.posthog_events i
  ON c.account_key = i.account_key
LEFT JOIN zetaris_legal.ironclad_contracts l
  ON c.account_key = l.account_key
WHERE c.scenario_key = 'shadow-discount-bluff'
WITH (ZETARIS_PUSHDOWN = TRUE, ZERO_ETL = TRUE);

05 · Sponsor Deep-Dive: Meterless Open Engines & Runtime Slide 06 / 08

How Meterless Was Used & What Made Our Approach Unique

1. Canonical H-MEM Hybrid Formula & TrustLedgerService

Implements the exact H-MEM specification (engines/hmem/AGENTS.md):

raw = 0.35·semantic + 0.20·keyword + 0.10·tag + 0.10·domain
    + 0.15·entity   + 0.05·layer   + 0.05·recency − 0.20·superseded
score = clamp01(raw) × confidence

Includes live interactive feedback buttons (👍 Helpful +0.05, 👎 Not Helpful -0.03, ⚠️ Wrong -0.20 + review) and logs all 17 canonical audit actions to TrustLedgerService.

2. Scout Intent 5-Stage Signed Execution Contracts

Implements Sense → Interpret → Guard → Route → Recommend (engines/scout-intent/AGENTS.md), issuing an immutable hmac-sha256 signed ExecutionContract with a 5-layer guard stack before any Zetaris query runs.

3. Outcome ROI & Margin Protection Circuit Breaker

Instead of billing per raw token, our Meterless ledger tracks Verified Margin Protected ($22,940–$28,200 per deal) vs. outcome unit cost ($0.0018 cloud equivalent / $0.00 on local Nightshift hotspot).
